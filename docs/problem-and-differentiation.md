# Problem and Differentiation

## What Already Exists
Reconciliation systems, settlement reports, matching engines, audit trails,
exception workflows, fuzzy matching, AI-assisted reconciliation, and historical
exception memory already exist in the financial-software market.

AstraLedger does not claim to be the first reconciliation tool.

## What We Focus On
AstraLedger focuses on an Evidence-First Exception-to-Prevention Loop for
merchant settlement operations.

## The Gap
Finance teams may repeatedly investigate the same delayed settlement, incorrect
fee rule, duplicate import, or source-format issue. A normal reconciliation
workflow often ends after it marks the item as matched, unmatched, or resolved.

AstraLedger converts that repeated exception into a controlled prevention cycle:

Exception
→ evidence
→ root-cause category
→ ownership
→ review and resolution
→ cross-cycle memory
→ repeated-pattern detection
→ prevention policy proposal
→ historical simulation
→ manager approval
→ scoped/time-limited activation
→ rollback capability
→ recurrence measurement

## Key Claim
AstraLedger does not reduce alerts by hiding them.

It reduces avoidable alert noise while keeping genuine missing-money risk
visible. A delayed settlement is marked “Expected Pending,” not “Resolved,”
until evidence of bank credit exists.

## Why This Matters
A finance team should not manually solve the same operational failure every week.
It should learn from recurring exceptions, safely improve its workflow, and
retain evidence for every financial decision.
